Architecture overview

Factory Inventory Management System

A two-tier demo app: a Vue 3 single-page app talks over HTTP/JSON to a stateless FastAPI service that serves and filters mock data loaded from JSON files at startup. There is no database, no authentication and no persistence.

6Routed views
15API endpoints (all GET)
7JSON data files
250Mock orders (2025)
32Inventory SKUs, 3 warehouses

System architecture

Two processes on localhost. The browser loads the SPA from Vite (port 3000), then calls the API directly on port 8001; Vite does not proxy API traffic.

Data flow: changing a filter

The main interaction loop. Four global filters drive every data view.

  1. User picks a filter in FilterBarTime period, warehouse, category or order status.
  2. Shared refs update in useFiltersRefs live at module scope, so every component shares one copy (singleton).
  3. Views react via watch()Each view watches only the filters it cares about and calls its loadData().
  4. getCurrentFilters() → api.jsMaps selectedLocation to warehouse and period to month; values of "all" are left out of the query string.
  5. FastAPI filters in memoryapply_filters() does exact warehouse match and case-insensitive category and status match; filter_by_month() handles 2025-03 or Q1-2025.
  6. Pydantic serializes the responseTyped endpoints validate against models; summary, spending and report endpoints return plain dicts.
  7. View stores raw data in refs, derives the restTotals, chart series and tables are computed(), then translated and formatted by useI18n.

Things worth knowing

Gaps found while reading the code and probing the running server.

Broken

api.js calls /api/tasks and /api/purchase-orders, but the backend doesn't define them.

Both return 404. The tasks modal in App.vue and the purchase-order flow in BacklogDetailModal can't save anything.

Unrouted

views/Backlog.vue exists but has no route in main.js and no nav link.

Backlog data appears only through the Dashboard.

Inconsistent

Reports.vue calls axios with a hardcoded URL instead of going through api.js.

The API base URL is also hardcoded in api.js; there is no env-based config.

Hardcoded

Quarter logic is fixed to 2025 (QUARTER_MAP and the reports endpoint).

Month filtering also uses a substring match on order_date, not date parsing.

Filters

total_backlog_items in the dashboard summary ignores every filter.

The other summary fields respect warehouse, category, status and month.

Demo only

No auth (useAuth returns a mock user), wildcard CORS with credentials, no persistence.

Fine for a workshop; not production-ready, as the README states.
